# 网页体验审计

先确认页面、视口和主任务。每条结论标明证据类型：截图观察、代码证据，或猜测。没有证据就写未证实，不把猜测当成缺陷。

## 检查

- 窄屏导航：主导航在小屏可打开、可关闭，且能到达主任务，不被次要入口淹没。
- 按钮层级：主操作唯一且可辨认；次操作不能在尺寸、颜色或位置上压过主操作。
- 行长与对比：正文行长适合中文阅读；文字与背景对比足以辨认，不以装饰牺牲可读性。
- 触控尺寸：可点控件有足够间距，避免相邻目标误触。
- 表单反馈：错误、成功和提交中状态可见，并说明下一步。
- 焦点：键盘焦点可见，且顺序符合任务。
- 动效：动效短、可预期，不阻挡阅读或操作。

## 禁止

不建议跟踪脚本、弹窗骚扰或虚假客户证明。截图里看不见的功能、文案和数据不要编造。

## 审美判断

缺陷检查通过后，还要判断页面是否有明确的视觉主张。参考一流编辑与产品设计的方法，不复制其版式、图片或标识：

- 编辑设计：像 Pentagram 与优秀新闻设计那样，用字号、字距和留白建立层级，而不是用相同的卡片填满页面。
- 产品界面：像 Stripe 与 Linear 那样，让一个主动作最清楚，其余动作安静。
- 中文阅读：标题可用衬线体，正文保持舒适行长；避免大面积英文装饰字。

每条审美意见必须指出截图中的具体位置，并说明它影响的是注意力、阅读节奏还是信任感。没有更好方案时，不为了“更时尚”改动已有品牌色。
