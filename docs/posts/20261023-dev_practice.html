AI 开发实践与部署（2026-10-23）

实践参考，未经运行验证。

本期主题

本期简报聚焦于两大热门框架的最新结构与功能改进：

  • PyTorch AOTI Runtime：将 ModelPool 迁移至独立头文件，提升模块化与单元测试可行性。
  • FastAPI：从 0.160.0 开始引入参数模型 extra 配置一致性、可组合表单模型联合以及可空表单联合的 OpenAPI 修复。

实践步骤

1. PyTorch AOTI Runtime

  1. 更新头文件引用
    • 将原先 model_container.h 中对 ModelPool 的引用改为 aoti_runtime/model_pool.h。
    • 确保编译器能够找到 aoti_runtime/ 目录。
  2. 单元测试
    • 参考 PR 201508 的单元测试实现，使用假模型验证 ModelPool 的行为。
    • 由于 ModelPool 现在与 model_container.h 分离，测试文件可单独编译。

2. FastAPI

  1. 升级至 0.160.0 及以上
    • 通过 pip install fastapi>=0.160.0 或更新 pyproject.toml。
  2. 参数模型 extra 行为
    • 在定义查询、头部、Cookie 或表单参数模型时，确认 extra 设置（forbid、allow、ignore）会影响同一位置的所有字段。
  3. 表单模型联合
    • 0.161.0 版本新增对表单模型联合的支持。
    • 0.161.1 版本修复了单独可空表单联合的 OpenAPI 架构。
    • 在需要多种表单输入时，可使用 Union 或 Optional 组合，但需遵循官方文档说明。

验证清单

项目 验证方式 预期结果
PyTorch 头文件路径 编译项目，检查是否能找到 aoti_runtime/model_pool.h 编译通过，无路径错误
PyTorch 单元测试 运行 ModelPool 的单元测试 所有测试通过，输出符合预期
FastAPI 版本 fastapi.__version__ 版本号 ≥ 0.160.0
参数模型 extra 发送包含额外字段的请求 根据 extra 设置，字段被拒绝、保留或忽略
表单联合 发送多种表单组合请求 API 正确解析并返回预期结果
OpenAPI 兼容性 访问 /openapi.json JSON 结构符合 0.161.1 的修复规范

限制与风险

  • PyTorch：摘要未说明此改动适用于哪些 PyTorch 主线版本；若使用旧版本，可能不兼容。
  • FastAPI：表单联合与可空联合的具体实现细节未在摘要中给出，使用时需参考官方文档或源码。
  • 兼容性：若项目中同时使用旧版 model_container.h 或 FastAPI <0.160.0，升级后可能导致编译或运行错误。
  • 测试覆盖：单元测试仅覆盖 ModelPool 的基本功能，复杂场景需自行扩展。
