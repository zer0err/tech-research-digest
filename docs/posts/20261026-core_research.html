RESEARCH BRIEF · 智能硬件技术专题

高效 AI、模型压缩与端侧适配（2026-10-26）

AI 分析：Xiaomi MiMo

依据公开来源自动整理，请核对证据边界。

本期结论

  • 两项研究均通过"减少主干模型参与的计算量"换取效率提升：SEMAC 将 HOA 传输通道从 36 降至 16，Deco 用轻量解码器替代主干执行全部 beam search [1][2]。
  • 在受限资源下，"低精度全量计算"未必优于"低维子空间+结构先验"：SEMAC 摘要指出，编码更少传输通道加方向包络在感知上优于对全部 HOA 通道做低精度编码 [1]。
  • 值得关注的信号：Deco 摘要称蒸馏可进一步提升轻量解码器精度，但摘要未提供蒸馏前后具体数值对比，无法从摘要确认增益幅度 [2]。

逐项分析

[1] SEMAC

  • 核心贡献：针对高阶 Ambisonics（HOA）码率随球谐阶数平方增长的问题，提出用量化全阶方向能量包络加更少 CELT 传输通道表示 HOA 信号 [1]。
  • 方法与数据：将 CELT 的"能量包络与信号形状分离"原理推广到方向信号；解码端在低维子空间重建后重新施加编码端观测到的全阶包络 [1]。
  • 性能证据：五阶素材 MUSHRA 主观测试，对比 Opus CMF3，512 与 768 kbit/s 两档；16/36 传输通道配置在两档下评分均高于全阶 CMF3，同通道数下高于阶数截断 [1]。
  • 局限与证据等级：摘要未给出具体 MUSHRA 分数、置信区间、客观指标（如 PESQ/STOI）或延迟/内存数据；证据等级 A（含方法、数据集与定量比较方向），但定量数值缺失 [1]。
  • 工程意义：适用于空间音频流式传输带宽受限场景；需自行评估解码端包络重施加的算力与内存开销，摘要未提供 [1]。

[2] Deco

  • 核心贡献：生成式推荐中，历史输入为 TK 个 code token、beam search 每步均过主干导致 O(BK) 解码 token 成本；Deco 将"读历史"与"写标识符"解耦 [2]。
  • 方法与数据：主干将每个历史条目融合为单 token，一次性压缩为紧凑"下一物品概念"；轻量 KV 缓存解码器基于该概念与已生成前缀执行完整 beam search，标识符、trie 与自回归分解保持不变 [2]。
  • 性能证据：电商、电影、音乐流媒体共七个数据集；在 50 ms p95 延迟预算下，吞吐达标准生成式推荐器与融合输入全主干教师的 3.2–8.6 倍，精度相当或更优 [2]。
  • 局限与证据等级：摘要未说明轻量解码器参数量、内存占用、功耗及各数据集具体精度数值；蒸馏增益未量化；证据等级 A（含方法、数据集与定量吞吐结果），但资源维度数据缺失 [2]。
  • 工程意义：适合候选预算 B 大、SID 深度 K 深的在线推荐服务；落地需自行测量解码器内存与 KV 缓存随并发的增长情况，摘要未提供 [2]。

工程行动建议

  • 验证实验：复现 SEMAC 16/36 通道配置在目标码率下的 MUSHRA 主观测试，并补充客观指标与解码延迟测量 [1]；复现 Deco 在 50 ms p95 预算下的吞吐与精度，记录解码器参数量与峰值内存 [2]。
  • 落地评估：SEMAC 需评估目标设备上包络重施加的算力与内存增量；Deco 需评估 KV 缓存随并发增长对内存的影响，摘要均未提供相关数据，无法从摘要确认 [1][2]。
  • 后续跟踪指标：SEMAC 跟踪更低码率档位与其他阶数下的表现及客观指标；Deco 跟踪蒸馏前后精度差、解码器参数量、不同 B/K 组合下的吞吐与内存曲线 [1][2]。
