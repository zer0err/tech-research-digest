提示词不是口号，也不是越长越好。应用中的提示词应把“长期规则”“本次问题”“可信资料”和“输出要求”分开。本课用一个会记录输入的离线模型检查程序到底发了什么，不消耗 API 额度。

学完要交付什么

新增 src/manual_assistant/prompts.py 与 show_prompt.py。给定问题和两条资料，程序形成稳定、可读、可测试的模型输入；资料里若出现像指令的文字，只当资料，不当命令。

一、四个部分各负其责（0–25 分钟）

我们采用四部分：

  1. 长期规则：角色、证据边界和不知道时的行为；
  2. 用户问题：用户真正想问什么；
  3. 参考资料：检索得到的原文，附稳定编号；
  4. 输出合同：回答必须满足的格式。

不要把密钥、私人资料或整份无关文档塞进提示词。模型能看到的内容都应视为已发送给服务商。提示词只能降低风险，不能保证模型永远遵守，因此后面还要程序校验。

五、排错与验收（110–120 分钟）

问题 修正
所有内容挤成一行 检查字符串中的 \n 和括号拼接
资料编号丢失 用数据中的稳定 id，不要按列表位置临时编号
提示词包含真实密钥 立即撤销密钥并清理历史；提示词函数不得接收密钥
空问题也调用模型 在构造输入时先 .strip() 并抛出错误

完成标准：能指出四个区段；离线记录替身只有一次调用；空资料练习三项均为 True；能解释“提示词规则”和“程序校验”的区别。
