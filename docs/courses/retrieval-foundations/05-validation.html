零基础路线 · Python 3.12 · 预计 120 分钟 · 本课不调用 AI、不访问外网

上一课我们把读取和查找写成函数，但程序仍然相信文件里的每一条记录都是正确的。今天要改变这个假设：文件能打开，不代表 JSON 合法；JSON 能解析，也不代表它具有我们需要的字段。

本课交付一个可被后续课程复用的 manual_core.py。它会先验证资料，再开始查找；出现问题时明确指出原因，而不是编造缺失信息或悄悄跳过坏记录。

时间建议：升级资料 15 分钟，理解校验规则 20 分钟，完成程序 35 分钟，主动制造错误 20 分钟，原创练习及验收 30 分钟。预计时长允许按自己的节奏调整。

逐行理解新增概念：

  • isinstance(value, list) 检查它是不是列表；str 表示文字，dict 表示字典。
  • enumerate(..., start=1) 同时取出编号和记录，让错误提示能说“第几条”。这里的 number 只是报错用的位置，不是稳定的资料 id。
  • set(document) 得到字段名的集合。集合不关心顺序，所以 JSON 中先写标题还是先写编号都没关系。
  • raise ValueError(...) 主动报错并停止当前函数。它与 print 不同：打印错误后函数仍可能继续，而抛出异常会交给外层处理。
  • try 放可能失败的操作；except 分别处理已知失败；else 只在读取和校验都成功时执行。不要写一个空的 except: pass 把所有问题藏起来。
  • if __name__ == "__main__": 让直接运行文件时调用 main()，但被其他程序 import 时不自动运行演示。这为下一课的测试作准备。

本例的演示查询固定为 usb，因此演示代码读取第一个结果。实际接收任意查询的应用仍要检查结果是否为空；不要把这一行直接当成完整问答程序。

六、排错与自查（115–120 分钟）

现象 优先检查
No module named 'manual_core' 两个 .py 是否在同一目录，文件是否误存为 .py.txt
提示只能包含三个字段 是否还在用未添加 id 的旧数据，或误拼字段名

资料文件报 JSON 错误 是否用了中文引号、末尾多余逗号；不要先怀疑校验函数
