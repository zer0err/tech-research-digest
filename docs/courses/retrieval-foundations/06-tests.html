零基础路线 · Python 3.12 · pytest 8.4.2 · 预计 120 分钟

你已经会手动运行程序，看结果对不对。但随着功能增加，每次都重新输入中文、英文、空格，再故意破坏数据，很容易漏掉一步。本课把这些操作变成自动测试：以后修改程序，只需运行一次命令，就能检查已约定的行为有没有被破坏。

本课不调用模型，不使用真实账号或密钥。第一次获取 pytest 可能下载软件包，测试本身完全离线。测试通过只覆盖我们写下的用例，不等于软件绝不出错。

建议安排：检查起点和安装 20 分钟，写第一组测试 25 分钟，扩展八类行为 35 分钟，观察一次失败 15 分钟，原创练习和复盘 25 分钟。

测试文件以 test_ 开头，函数名也以 test_ 开头，pytest 才能按默认规则找到它们。你不需要在文件末尾手动调用这些函数。

每个测试都分为三步：准备资料；调用要检查的函数；用 assert 对照预期。assert 放在测试中很合适，但不能替代第五课面对外部数据时的正式校验。Python 的优化运行模式可能禁用断言，所以程序必须保留 raise ValueError(...)。

为什么不让 AI 判断答案对不对？本课的“应找到 battery”“空输入应返回空列表”已经可以精确比较，用确定性的测试更清楚，也不会消耗模型额度。

现在把 test_manual_core.py 整体替换为下面的完整版本：

运行同一条测试命令，必须是 8 passed。不是 7 passed，也不是“没有报错就算通过”；数量减少可能意味着某个函数名拼错，没有被执行。

新增语法不用一次全背下来：

  • [item["id"] for item in results] 是列表推导式。它逐条取出编号，生成新列表，相当于先建空列表，再循环 append。
  • deepcopy 创建独立副本，方便比较查找前后原数据是否改变。直接写 before = documents 只会让两个变量指向同一对象，可能漏掉修改。
  • with pytest.raises(ValueError) 表示我们预期这段代码应当报错；如果它没有报错，测试反而失败。match 还检查错误信息的关键部分。
  • tmp_path 是 pytest 提供的独立临时目录。把它写在测试函数参数里，pytest 会传进来。坏 JSON 只写入这个临时位置，不会破坏你的正式资料。

这八个测试分别约束行为，不是八次重复运行同一个例子。

六、排错、验收与边界（115–120 分钟）

现象 应检查什么
No module named pytest 是否漏了 --with pytest==8.4.2，或没有使用整条 uv 命令
no tests ran 文件名、函数名是否以 test_ 开头；当前目录是否正确
重复编号测试失败 第五课是否还停留在没有 seen_ids 的第一版
documents.json 找不到 测试文件是否和资料文件放在一起；不要改成不明绝对路径
明明失败却看到 [100%] 100% 是测试执行进度，不是正确率；看最终 passed/failed
下载失败 第一次安装 pytest 需要网络；不要因此换成其他版本或关闭证书校验

本课验收：版本为 8.4.2；全部九项通过；你亲自制造过一次失败并恢复；不会把测试通过说成“事实已经全面验证”。输入长度限制、数据规模、网络失败与模型输出还不在这九项覆盖范围内，后面的单元会逐步增加。
