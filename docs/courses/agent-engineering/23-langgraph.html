学习目标与先修

把任务分解为有状态节点，掌握失败分支、恢复与人工介入。

先修：能使用Python函数、列表、字典、虚拟环境与命令行；第01单元无需模型训练知识。其余单元按系列README的主线/支线路线学习，目录顺序不是强制先修链。训练选修先完成02与12单元，领域项目先完成15、16与12单元，综合项目先完成01、15、16、22、23单元。

概念与工程边界

LangGraph适合显式表示状态与流转。多Agent只有在职责可分离、并行收益或专门检查有实证价值时才值得引入；多个模型来回对话也可能放大错误、延迟和成本。框架的checkpoint不能自动使外部写操作具备幂等性。

实践步骤：从基础实验走向真实项目

先用确定性状态机观察无资料拒答；再用固定响应节点实现LangGraph；逐步接入检索与真实模型；模拟某节点失败并恢复；最后对比单Agent与检索者/回答者/检查者三职责设计。

建议将过程分为：20分钟概念与环境核对、25分钟基础实验、45分钟实训/设计、30分钟排错与记录。依赖尚未锁定时，先完成方案，不执行来源不明的一键安装脚本。

框架实验开跑前建立experiment.json，至少填写：Python与平台、库版本、模型或数据revision、数据许可、随机种子、输入上限、费用上限、测试命令、预期条件、实际结果、产物哈希。版本字段不能填“latest”冒充可复现版本；没有GPU或付费API授权时，不租机或发送请求。

本单元练习与验收

  1. 基础实验：运行命令，解释每个字段；将一个合法输入改成边界/非法输入，记录程序行为。重点不是复制JSON，而是说明该实验没有验证什么。
  2. 设计练习：在条件边没有停止分支时容易无限循环；把所有历史消息无界追加也会消耗上下文和预算。
  3. 实训练习：状态包含任务ID、已执行工具、错误与预算；恢复不会重复副作用；多Agent方案必须报告比单Agent增加的成本与实际收益。

交付一份短报告：任务定义、输入、版本、测试、观察、失败案例和未验证项。第三项未完成时不要勾选实训，也不能因全部基础实验能运行就宣称掌握了本单元框架。

排错与风险

在条件边没有停止分支时容易无限循环；把所有历史消息无界追加也会消耗上下文和预算。

失败时按数据→配置→模型/框架→资源→外部服务顺序收集证据。只改一个因素再复测。外部文档与模型回答都是不可信输入；密钥只从环境或平台密钥管理读取，不进入截图、工作流导出、网页和Git历史。
