# VORASIO AI 生态工具目录需求与实施规范

状态：阶段 A、B 已完成；阶段 C 待实施
版本：1.0
日期：2026-10-29
范围：AI 生态工具固定模块；不包含课程、每日资讯时间线和广告投放系统。

## 1. 产品目标

工具目录是一个可检索、可核验、持续维护的 AI 产品索引，不是每日新闻，也不是自动生成的“排行榜”。它帮助读者回答四个问题：

1. 我现在要完成什么任务，应该看哪一类工具？
2. 该工具在我的所在地区是否可注册、访问和付费？
3. 是否有可核验的免费方案，免费到什么程度？
4. 信息何时核验、证据来自哪里，是否可能已经变化？

目录与资讯文章应分开：资讯时间线记录“发生了什么”，工具目录记录“目前可用什么”。同一产品可以被资讯文章引用，但目录只保留一条规范化记录。

## 2. 信息架构

### 2.1 顶层入口

- `/tools/`：目录首页，包含任务搜索、领域入口、最近核验和最近更新。
- `/tools/category/<slug>/`：领域页。
- `/tools/<tool-slug>/`：工具详情页。
- `/tools/changes/`：重要新增、下架、价格或可用性变化记录。

首页默认按“使用任务”组织，而不是先让用户选择国家或价格。推荐入口顺序：

1. 搜索框：支持产品名、公司名、任务和标签。
2. 常用任务快捷入口。
3. 领域分类。
4. 最近核验与重要变化。
5. 数据口径和纠错入口。

### 2.2 一级领域

每个工具只能有一个 `primary_category`，可有多个 `capabilities`，防止同一产品在各板块重复出现。

| 一级领域 | 典型能力标签 |
|---|---|
| 通用助手与文本 | 对话、写作、翻译、总结、办公问答 |
| 搜索与研究 | 联网搜索、论文检索、知识库、引用核验 |
| 编程与开发 | 代码补全、IDE、代码审查、测试、部署 |
| 图像与设计 | 文生图、编辑、设计、演示、UI |
| 视频 | 生成、剪辑、数字人、字幕、视频理解 |
| 音频与音乐 | 语音合成、识别、降噪、配音、音乐生成 |
| Agent 与自动化 | 工作流、浏览器操作、多 Agent、集成 |
| 数据与分析 | 表格、BI、SQL、数据清洗、可视化 |
| 模型、API 与基础设施 | 模型 API、推理、训练、评测、向量数据库、GPU |
| 端侧 AI 与智能硬件 | 本地推理、嵌入式、机器人、开发板、设备 SDK |
| 学习与教育 | AI 学习、辅导、课程辅助、教育应用 |

若将来某一类有效工具少于 5 个，不单独建立空板块，暂时作为能力标签并入最接近的一级领域。

### 2.3 结构化筛选维度

以下均为正交维度，不应混成层层嵌套的目录树：

- 服务区域：`中国大陆可直接使用`、`海外服务`、`跨区域`、`可用性待核验`。
- 价格形态：`免费开源/本地运行`、`永久免费层`、`免费试用/赠送额度`、`付费`、`价格待核验`。
- 使用形态：Web、桌面、移动端、API、插件、本地部署、硬件。
- 用户类型：个人、开发者、团队、企业。
- 数据处理：云端、可本地、混合、未确认。
- 核验状态：已核验、部分核验、待复核、已失效/停止收录。

“大陆/海外”描述的是用户可用性，不用于判断公司国籍：

- `中国大陆可直接使用`：官方条款或实际注册路径表明大陆个人用户可正常访问、注册；支付可用性单独记录。
- `海外服务`：官方面向海外市场，或大陆访问、手机号、支付存在明确限制。
- `跨区域`：大陆与主要海外地区均有官方可用路径，且产品能力大体一致。
- 不使用 VPN、转售账号或非官方镜像证明“可用”。不确定时必须标为待核验。

### 2.4 免费与收费的显示规则

页面不强制显示空分组。“没有免费方案”时只显示已核验的付费方案，不出现空的“免费”标题；反之亦然。

免费必须进一步区分：

- `免费开源/本地运行`：软件许可证允许免费使用；硬件、算力、模型权重许可另行说明。
- `永久免费层`：官方长期免费层，必须记录主要限额和核验日期。
- `免费试用/赠送额度`：必须记录期限、额度、是否要求信用卡和到期行为。
- “免费下载安装”“免费注册”“联系我们获取价格”不能推断为免费使用。

价格以官方定价页为准，目录默认不换算汇率，不承诺含税价。复杂的按量计费只展示计费单位和官方链接，不复制一整张容易过期的价格表。

## 3. 单个工具的数据契约

建议以仓库内 YAML/JSON 作为唯一事实源，再构建静态网页。最小记录如下：

```yaml
id: example-tool
name: Example Tool
provider: Example Inc.
official_url: https://example.com/
primary_category: video
capabilities: [text-to-video, editing]
summary_zh: 一句话说明它解决什么问题，不写宣传口号。
regions:
  availability: overseas
  registration: verified
  payment: unknown
  notes_zh: 中国大陆注册与支付情况未确认。
access: [web, api]
audiences: [individual, developer]
pricing:
  modes: [free_trial, paid]
  free_note_zh: 官方提供一次性赠送额度；具体数额见定价页。
  card_required: unknown
  pricing_url: https://example.com/pricing
deployment: cloud
evidence:
  - kind: official_product
    url: https://example.com/product
  - kind: official_pricing
    url: https://example.com/pricing
verified_at: 2026-10-29
status: active
editorial:
  strengths_zh: 适合什么场景。
  limits_zh: 已知限制和不适合的场景。
  sponsored: false
```

必填字段：`id`、`name`、`provider`、`official_url`、`primary_category`、`capabilities`、`summary_zh`、`regions`、`access`、`pricing.modes`、至少一条官方证据、`verified_at`、`status`。

不得存储账号、密钥、邀请码、抓取到的个人信息或大段第三方介绍文本。

## 4. 纳入和排除规则

### 4.1 纳入条件

同时满足以下条件才可公开收录：

1. 有可识别的官方产品页、官方代码仓库或正式应用商店页面。
2. 能说明一个明确的 AI 能力和目标用户，而非只包含模糊的 AI 宣传。
3. 至少一项关键信息可由一手来源核验。
4. 当前可以注册、下载、部署，或明确处于公开候补/测试阶段。
5. 不依赖破解、共享账号、绕过区域限制或侵犯版权的使用方式。

### 4.2 排除条件

- 只有软文、联盟营销页、聚合转载或无法确认归属的站点。
- 仿冒产品、恶意软件、高风险下载、账号交易、密钥转售。
- 仅有概念发布但无可访问产品；此类内容可进入资讯，不进入目录。
- 已停止服务、长期无法访问且没有可用开源版本。
- 官方条款明显禁止目标用途，却以“技巧”绕过限制。
- 无法核验却声称永久免费、无限量或保证收益。
- 内容高度重复的白标产品；默认保留可确认的原始服务商。

### 4.3 质量与排序

不生成含糊的总分，也不声明“最好”。目录默认排序依次为：

1. 与当前筛选条件的匹配度；
2. 证据完整度；
3. 最近核验时间；
4. 产品名称稳定排序。

可以提供“适合新手”“可本地部署”“有 API”等事实型徽标。性能、效果或市场排名只有在存在可比较证据时才展示，并注明测试条件。

## 5. 自动采集与更新

### 5.1 来源优先级

1. 官方产品、文档、定价、服务状态和条款页面。
2. 官方 GitHub 仓库、正式应用商店和官方公告。
3. 用于发现线索的可信目录、搜索或媒体；只能触发待核验候选，不能直接公开。

禁止让生成模型仅凭记忆写入价格、区域可用性或“免费”状态。

### 5.2 更新管线

```text
发现候选 → 规范化 URL/名称 → 去重 → 获取官方证据
→ 规则校验 → AI 仅做摘要与分类建议 → 生成变更草稿
→ 确定性检查 → 发布静态目录 → 记录变更与核验日期
```

自动化应区分三类动作：

- 新增：默认进入候选区；官方证据齐全后才能公开。
- 更新：价格、免费层、区域和服务状态变化需保存字段级差异。
- 下架：先标记 `unavailable`，保留短期变更记录；从默认目录隐藏但不立即抹除历史。

推荐频率：

- 每日发现新候选，但没有合格候选时不发布空内容。
- 每周复核高变化字段：价格、免费额度、新增/关闭服务。
- 每 30 天复核活跃工具的官方链接和基础信息。
- 超过 45 天未核验显示“信息可能已变化”；超过 90 天进入待复核，默认不展示免费承诺。

### 5.3 去重

- 规范化官网主域名、官方仓库和 provider + product 名称。
- 同一产品的 Web、App、API 作为一条记录的多个使用形态，不拆成多个工具。
- 产品家族只有在能力、定价和入口明显独立时才拆分。
- 改名保留原 `id` 和别名，避免重新生成页面和重复收录。
- 目录与每日资讯分别去重；资讯出现过不阻止工具进入目录。

### 5.4 发布门槛与无效内容防护

公开构建必须拒绝：

- 缺少官方 URL 或核验日期；
- 分类、区域、价格枚举不合法；
- 声称免费但没有官方价格/计划证据；
- 重复 ID、重复规范官网或重复详情页；
- 摘要为空、只有营销形容词或与证据不一致；
- 链接返回明显错误、跳到无关域名或存在不安全协议。

失败条目留在候选报告中，不生成空卡片，不让模型补齐未知事实。一次候选失败不应阻断已验证目录的正常构建。

## 6. 页面呈现与交互

工具卡片只展示用于选择的摘要信息：名称、任务说明、主要能力、区域、价格形态、使用形态和最后核验日期。详情页再展示：

- 适合与不适合的场景；
- 免费/付费边界和官方定价链接；
- 注册、支付和区域限制分别说明；
- 云端/本地及数据处理提示；
- 官方产品、文档、价格和开源仓库链接；
- 最后核验时间、变更记录、纠错入口；
- 商业关系披露（如存在）。

移动端使用可横向滚动的筛选标签或筛选抽屉，不使用宽表格作为主要浏览界面。任何颜色徽标都同时显示文字，保证无障碍识别。

URL 应保存筛选参数，便于分享，例如：

`/tools/?category=audio&region=mainland&pricing=free-tier`

当组合筛选没有结果时，显示“当前没有符合且已核验的条目”，并提供清除部分筛选，不生成推荐内容填空。

## 7. 广告与商业化兼容边界

当前阶段不接入广告代码，但数据和布局预留以下能力：

- `sponsored`、`commercial_relationship`、`disclosure_text` 字段。
- 固定广告槽只能位于列表区块之间或详情页独立区域，不伪装成工具卡片。
- 赞助内容必须显著标注“广告/赞助”，不得复用“编辑推荐”样式。
- 付费关系不得改变工具的事实字段、核验门槛和自然排序。
- 联盟链接须明确披露，并同时保留可识别的官方直接链接。
- 不向广告脚本发送用户的本地课程进度、搜索词或敏感偏好。
- 未经同意不引入跨站追踪；广告平台接入前单独完成隐私、Cookie、地域法规和性能评审。

商业化可影响广告位展示，不能影响目录纳入、排除、价格判断和“免费”标签。

## 8. 与现有系统的边界

- 课程是经过验证的固定学习内容；工具目录不得自动向课程正文插入会变化的推荐。
- 每日资讯可链接目录详情页；目录详情页可列出最近相关新闻，但二者数据源和去重状态独立。
- 晨间免费资源是“当天新线索”，工具目录是“持续有效记录”。新线索只有通过本规范的证据门槛后才进入目录。
- Groq、MiMo 或未来模型可以协助生成中文摘要、能力标签建议和差异说明，但价格、区域、官方链接、核验日期必须由采集证据和确定性规则产生。
- 模型失败时保留上次已验证目录，不发布半成品或空页面。

## 9. 分阶段实施与验收

### 阶段 A：数据与规则

- 建立 JSON Schema/YAML Schema 和枚举。
- 准备 12–20 个跨领域样例，覆盖大陆、海外、跨区域与各价格形态。
- 实现 URL 规范化、重复检查、官方证据和免费标签校验。

验收：错误的免费声明、重复工具和缺证据记录均使校验失败。

### 阶段 B：静态目录

- 构建目录首页、领域页和详情页。
- 实现任务搜索、组合筛选、空结果与移动端布局。
- 显示来源、核验日期和商业披露字段。

验收：无 JavaScript 时仍能浏览领域页和详情页；移动端无横向溢出；筛选 URL 可分享。

### 阶段 C：自动更新

- 建立候选发现、证据获取、字段差异、待复核和下架流程。
- 将每日新线索与目录状态去重。
- 失败不覆盖上一版有效输出。

验收：无合格新增时网站不生成空卡；一次来源或模型故障不破坏现有目录。

### 阶段 D：商业化准备（暂不实施）

- 完成赞助披露、广告槽、隐私和性能方案。
- 在接入任何广告 SDK 前单独获得批准。

## 10. 当前明确不做

- 不做未经证据支持的 AI 总榜或自动“十大推荐”。
- 不抓取并转载第三方目录全文。
- 不接受厂商自行提交后立即公开。
- 不把试用、赠送额度或开源代码一律称为“免费”。
- 不因广告或联盟收入修改自然排序。
- 不在本阶段建立登录、收藏同步、评论、付费会员或广告系统。

## 11. 2026-10-29 实施记录

阶段 A 已建立 `config/tools.json` 与 `research_bot/tool_catalog.py`。首批 14 条记录全部采用可本地运行的官方开源项目，逐条保存官方仓库、官方许可、能力、运行形态、地区口径和核验日期；“免费开源”只描述软件许可，不推断模型权重、硬件、云服务或外部模型调用免费。

确定性校验会拒绝重复 ID、重复规范 URL、非 HTTPS 地址、缺少官方证据、缺少核验日期、非法分类/地区/价格枚举，以及没有官方许可证据的“免费开源”声明。

阶段 B 已完成总目录、搜索、领域与使用方式筛选、URL 状态恢复、无 JavaScript 阅读、空结果处理、首页与主导航入口，以及 320px 移动端规则。由于首批 14 条均为免费开源、本地运行项目，页面明确标注首批范围，暂不展示没有区分度的地区和价格筛选，也不生成稀疏分类页。待阶段 C 补齐大陆、海外、免费层、试用和付费产品并完成逐条核验后，再开放对应维度。
