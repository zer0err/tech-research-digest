# VORASIO AI 学习课程：需求及技术方案

> 状态：依据用户最新范围纠偏，实施中；文档不代表成果已交付
> 版本：0.6
> 更新日期：2026-10-28
> 适用站点：`vorasio.com`

## 1. 决策摘要

VORASIO 新增完整的 AI 开发学习路线。课程由 Codex 使用经确认的 GPT-6 高级模型提前整套创作、自查和实测，通过门禁后一次性发布全部单元。课程不采用逐日定时释出，不建设课程管理后台，不加密课程文件，也不新增 R2、D1、Cloudflare Access 或课程 Worker。

当前用户要求先完成整套课程，AI 生态工具目录明确暂缓，并非删除该需求。首套采用 **18 单元的完整闭环系列**，由零基础 Python 走到一个有真实模型接入路径、资料检索、引用、网页交互和测试的 AI 应用。课数是本轮实施选择，不是用户规定的最低课数；逐课地图与验收见 [`COURSE_CURRICULUM_MAP.md`](COURSE_CURRICULUM_MAP.md)。前三课仅是起点，不能作为整个目标已经完成的证据。

未发布草稿只保留在出版人与 Codex 共用的本地工作区，不推送到公开 GitHub 仓库。出版人本地预览并确认后，才把完整系列提交到公开网站。发布后的内容本来就是公开资料，加密没有意义。

现有资讯自动化、GitHub 定时任务和 `vorasio-editorial-watchdog` 保持不变；它们不参与课程创作或课程发布。

## 2. 产品目标

1. 建立按系列组织、循序渐进的 AI 开发课程；每个系列最多 30 个单元。
2. 每个单元预计学习与实践约 2 小时，读者自行安排节奏。
3. 整个系列在公开前完整生成、AI 自查纠错和程序验证，确保环境、术语、难度和项目连续。
4. 课程依据优质公开资料重新组织和讲解，保留出处，不整篇复制受版权保护内容。
5. 练习对应当前单元目标，系列内不机械重复，并与实际采用的参考课程习题比较，记录任务或数据的差异；不声称与全互联网所有习题均不相同。可执行代码必须在固定环境中真实运行并通过测试。
6. 每个单元末尾逐项列出该单元的练习，由读者手动勾选；学习进度仅保存在当前浏览器，不上传服务端、不要求登录。不得用一个整课勾选替代每项练习记录。
7. 全部单元通过门禁且出版人确认后，一次性公开整个系列。
8. 页面为未来讨论区和广告保留合理扩展位置，但首期不加载相关第三方脚本。
9. “能开发 AI 应用”的本套验收边界：读者能解释、修改并在本机运行资料问答应用，配置模型适配器、处理失败、返回可核对引用并运行评测。不宣传学完即掌握所有模型训练、微调、MLOps 或智能硬件开发。

## 3. 明确不建设的内容

- 不建设 `admin.vorasio.com` 或其他课程管理后台。
- 不保存长期未发布课程到公开仓库，因此不建设课程加密、密钥管理或解密服务。
- 不使用 R2、D1、KV 或额外数据库。
- 不建立课程 cron、逐日解锁、到期判断或课程漏跑补偿。
- 不提供课程用户账号、服务端学习记录或跨设备同步。
- 不设置或宣称存在专家审稿。
- 不让 Groq、MiMo 或 GitHub Actions 自动生成课程内容。

上述“无后台”指课程网站的管理与学习记录后台；教学项目可以包含只监听本机的开发服务，以讲解 AI 应用如何工作。它不是为 VORASIO 新增线上服务，也不自动部署至公网。课程作者不得把正文生成外包给 Groq/MiMo；读者学习模型 API 的教学示例与课程作者所用模型是不同概念。

如果未来出现多人远程协作、长期云端草稿、付费内容或跨设备进度等新需求，再重新评估后台、私有仓库或存储服务；不能提前为假设需求增加复杂度。

## 4. 职责

| 角色 | 职责 |
|---|---|
| 出版人 | 确认课程方向；本地预览；决定是否将完整系列公开；提出修订请求 |
| Codex 课程作者 | 使用 GPT-6 高级模型，根据蓝图和来源包生成课程 |
| Codex 自查员 | 在另一次检查回合复核引用、连续性、练习差异、事实边界和表达；可以是同一高级模型，不冒称独立专家或不同模型审稿 |
| 自动验证器 | 在确定性环境运行代码、测试和预期输出，不以模型判断替代执行 |
| 公开读者 | 阅读全部公开单元，在自己的浏览器中匿名记录学习进度并在后续讨论区反馈 |

出版人的确认属于产品和发布决策，不表述为专家审稿。

## 5. 课程内容模型

### 5.1 系列结构

每个系列包含：

- 系列 ID、中文名、英文名、目标读者和先修要求；
- 固定技术环境及锁定依赖；
- 公开参考课程、官方文档和许可/引用记录；
- 不超过 30 个单元的课程蓝图；没有 7 单元下限；当前首套选用 18 单元；
- 每单元目标、预计时长、前置单元、实战任务和验收标准；
- 系列级项目及最终成果；
- 内容版本、模型记录、AI 自查纠错记录和验证记录。

### 5.2 单元最低结构

1. 标题、系列/单元编号、预计用时和难度；
2. 学习目标和先修知识；
3. 固定环境说明；
4. 概念讲解；
5. 分步骤实战；
6. 可复制运行的完整代码；
7. 自动验证过的预期结果；
8. 独立练习和验收条件；
9. 常见错误、调试方法和边界；
10. 总结及下一单元衔接；
11. 参考来源、AI 生成模型、AI 自查模型和验证状态；
12. 文章末尾按练习分别设置手动复选框和完成标准，汇总本单元完成情况。

预计时长以约 120 分钟为设计目标，不设置未经用户要求的 90–150 分钟硬门禁。安装、网络和个人节奏会影响耗时；应提供安排估计，未实测学习者耗时不得写成保证。

### 5.3 固定技术环境

当前系列延续 Python 3.12 + uv；正文前三课已在 macOS + Python 3.12.12 上运行。优先使用标准库，后续确需依赖时一次锁定版本并给出完整安装说明，不在课间无说明切换环境。记录实际操作系统、补丁版本、包管理、依赖或“无第三方运行依赖”、硬件要求、项目结构和测试命令。确需升级时建立新系列或明确迁移单元；未实测的平台不标注已验证。

## 6. 来源和版权

### 6.1 来源优先级

1. 官方文档、标准、论文及维护者仓库；
2. 许可明确的开源书面课程；
3. 信誉良好的大学公开课程；
4. 其他可核验的技术资料。

搜索结果只用于发现，重要版本、API、安全和性能结论回到第一方资料核验。

### 6.2 使用边界

- 先比较少量适合零基础且许可明确的开源书面课程，说明选择依据；按许可获取相关章节/仓库并记录不可变版本，建立来源索引与本地参考副本。原创讲解和练习不等于可以跳过该来源工作。
- 保留上游版权与许可；不默认整篇转载。不能合法复制的内容只保留必要事实与链接，并明确未克隆的原因。
- 记录来源 URL、作者/机构、标题、访问日期、版本或 commit、许可及允许的使用方式。
- 许可不明确时只保存必要事实和链接，不保存或公开大段原文。
- 明确区分来源事实、教学解释和推导建议。
- 引用失效或版本变化产生维护事项，不静默替换历史依据。

## 7. Codex 与 GPT-6 政策

课程蓝图、正文、练习和教学解释均由 Codex 使用 GPT-6 级高级模型直接完成。用户没有限定 Astra 或 Sol，不再以某个未经用户指定的后缀作为唯一许可条件。不能静默改交其他服务或轻量模型；实际可用模型与要求不符时说明并等待选择。

| 环节 | 要求 |
|---|---|
| 蓝图与完整草稿 | Codex 使用 GPT-6 级高级模型，记录实际可核验型号或明确标注型号未知 |
| AI 自查纠错 | Codex 使用 GPT-6 高级模型开启独立自查回合，不把初稿当作既定事实 |
| 代码验证 | 确定性测试环境，必须实际执行 |
| 格式与元数据 | 优先使用确定性程序 |
| 发布 | 不调用任何模型，只提交已确认内容 |

- 现有 Groq 和 Xiaomi MiMo 资讯自动化不参与课程创作；教学项目使用哪种模型服务另行明确配置、费用和验证范围，不能将它混称为课程创作模型。
- 课程生成工具、静态构建与 GitHub Actions 不读取模型 API Key；教学项目若演示真实模型调用，只由学习者明确启用，密钥从本机环境读取，不进入网页、教程正文、日志或仓库。
- 每单元记录实际可核验模型信息、生成/检查时间、来源和内容版本；来源包/输出哈希作为可复核构建证据。未知型号必须如实标注，不能伪造 Astra 证据，也不能把自行添加的型号要求当作用户阻塞。
- 达到 Codex 使用限制时暂停，不降低模型等级。

## 8. 正确性与质量门禁

状态机：

`planned → sourced → drafted → ai_checked → tested → release_confirmed → published`

任一门禁失败进入 `needs_revision`。已发布内容的实质修订使用新内容版本和修订说明。

验收包括确定性自动检查与 AI 自查；两者不能混为一谈。仅校验元数据中的 `passed` 字符串不等于重新执行代码或证明事实正确。检查项包括：

- schema 和必填章节完整；
- 关键事实有可回查来源；
- 来源 URL、版本和许可字段完整；
- 系列环境与锁定依赖说明一致；纯标准库可明确无第三方依赖，不伪造 lockfile；
- 代码在干净环境中从零安装并运行；
- 单元测试、示例命令和预期输出一致；
- 不含密钥、个人信息、危险命令或未说明的外部写操作；
- 练习有稳定 ID、知识点和验收条件；人工可读的 AI 自查对照系列内及所采用上游课程，说明重复风险和任务差异；相似度工具若使用只作辅助，未实现时不声称已运行；
- 相邻单元衔接、先修关系和系列项目连续；
- 所有必需单元达到 `tested` 后才允许系列进入 `release_confirmed`。

模型教学示例区分“离线固定响应/本地假服务测试”与“真实模型联通实测”。离线测试验证请求构造、校验和错误处理，不证明真实模型质量；真实生成不要求逐字一致，改用输出结构、引用合法性及安全边界验收。缺少真实模型实测证据时列为未验证项，不伪造 API 调用、免费额度或效果。完整系列应有可实际配置的真实模型路径，不能只有假响应却称 AI 应用。

## 9. 草稿、预览与全量发布

### 9.1 未发布阶段

- 草稿保存在当前本地工作区的忽略目录中，不进入公开 Git 历史。
- 来源清单、测试结果和预览站点与草稿一起保存在本地。
- 通过本地静态预览检查桌面端、移动端、导航、代码块和本地进度。
- 未发布内容不上传 GitHub artifact、Pages 或第三方服务。
- 出版人确认前不执行 `git add`、提交或推送课程正文。

本地工作区不是永久备份。开始完整系列前，在同一设备的受控本地备份位置保存工作副本；备份方式不得把草稿同步到公开目录。

### 9.2 全量发布

- 任一必需单元未通过门禁时，整个系列不得发布。
- 出版人确认后，把完整系列、来源记录和公开验证摘要一次提交到站点。
- 发布不调用 AI，不使用课程定时器。
- 唯一键为 `series_id + lesson_id + content_version`。
- 重跑不得生成不同正文、重复通知或静默改变已发布内容。
- 全量上线可选择发送一次 Telegram，内容仅为系列名称和公开入口。

### 9.3 修订

- 小型文字修订保留内容版本兼容标记。
- 练习、环境或验收条件的实质变化提升内容版本并显示修订说明。
- 已发布版本不从 Git 历史抹除；明显错误可以从当前页面撤回，但保留审计记录。

## 10. 公开网站体验

- 首页增加“AI 学习路线”固定入口，与时效资讯时间线分区。
- 系列页显示目标、环境、全部单元和本地完成进度。
- 单元页移动端优先，代码块可横向滚动，提供章节目录和前后单元导航。
- 标题下结构化显示系列/单元、预计时长、难度、AI 生成模型、AI 自查模型、验证状态和来源。
- 每单元末尾显示所有必需练习的手动复选框；汇总本课与整个系列的进度，明确这是自我记录而不是系统评分。
- 为未来讨论区和广告保留语义容器，不加载第三方脚本。

### 10.1 匿名本地学习进度

- 只有读者主动勾选或取消时改变状态，不根据滚动、停留或打开页面自动完成。
- 使用 `localStorage`，按数据结构版本命名；现有 `vorasio.course-progress.v1` 仅记录整单元，新增练习粒度时需显式迁移或启用新版本，不能静默曲解旧记录。
- 新记录只包含 `series_id`、`lesson_id`、`exercise_id`、内容版本和手动勾选时间；不记录代码答案或聊天内容。
- 旧版整单元完成标记不能自动转为“所有练习已完成”，应保留为历史记录并提示读者逐项核对。
- 不写入 Cookie、GitHub、Cloudflare、Telegram、分析服务或服务端接口。
- 系列页显示练习与单元完成数量和百分比；本课所有必需练习已勾选才汇总为单元完成。同源标签页通过 `storage` 事件同步，不宣称事务级并发或跨设备同步。
- 提供“清除本系列进度”和本地导出/导入；清除前二次确认。
- 存储不可用时复选框仍可在当前页面工作，并提示无法持久保存。
- 换浏览器/设备、清理数据后不会自动恢复，也不提供跨设备同步。
- 普通修订保留完成状态；破坏性练习变化标记“建议重新学习”，不删除原记录。
- “匿名”仅指学习进度不上传、不绑定账号；托管平台和网络运营方仍可能保留常规访问日志。
- 使用严格 CSP，避免第三方脚本读取本地进度；首期不加载广告或第三方统计。

### 10.2 后续读者讨论与纠错闭环

课程发布稳定后开放文章讨论区，收集疑问、运行结果、错误报告和建议。讨论区不属于首期交付。

- 反馈类型：事实错误、代码无法运行、版本变化、表达不清、补充资料、一般讨论。
- 状态：`new → triaged → accepted/rejected → fixed`。
- 读者内容是不可信输入，需要反垃圾、频率限制、链接过滤和内容安全处理。
- 评论不能直接修改正文，也不能触发模型自动重写或发布。
- 被接受的反馈由 Codex 核对来源、复现问题并形成新版本。
- 实施前比较 GitHub Discussions、giscus 和自建方案的数据所有权、隐私、审核、登录门槛和成本。

## 11. 仓库与工作流

```text
course_work/                 # 本地草稿，gitignore，不推送
course_system/
  schemas/                   # 系列、单元、来源、验证记录 schema
  templates/                 # 课程与自查模板
  validators/                # 状态机、结构和发布门禁
docs/courses/                # 确认后才生成并提交的公开课程
docs/assets/course-progress.js
tests/course_fixtures/       # 非正文的测试夹具
```

课程不需要后台 API。GitHub Actions 只承担提交后的确定性检查和现有 Pages 部署：

| 工作流 | 触发 | 作用 |
|---|---|---|
| `course-check.yml` | 课程文件变更 | 校验 schema、链接清单、版本、页面结构和安全规则 |
| 现有 Pages 部署 | 主分支变更 | 部署已提交的完整系列 |

本地课程预览和首次发布由 Codex 在当前工作区完成，不建立课程 `workflow_dispatch`、课程 Token 或 Cloudflare Worker。

## 12. 安全与隐私

- 未发布草稿只存在于本地忽略目录，不进入公开 Git、artifact 或 Pages。
- 发布前运行 secret 扫描和暂存区检查。
- GitHub Actions 固定第三方 Action SHA，权限最小化。
- 课程 Markdown 禁止原始 HTML；渲染时转义模型输出。
- 公开页面使用严格 CSP，不引入不必要第三方脚本。
- 本地学习进度不包含姓名、邮箱、IP 或设备标识，也不上传。
- 后续讨论区单独制定身份、隐私和内容安全方案。
- 如果设备或本地工作区损坏，未发布草稿可能丢失；这通过本地受控备份解决，不通过公开仓库加密解决。

## 13. 成本

- 不新增 Cloudflare 后台、Access、R2、D1 或 Worker 成本。
- 课程创作不另外调用 OpenAI/Groq/MiMo 生成 API，消耗当前 Codex 账户使用额度。教学项目的真实模型请求单独说明潜在费用、配置方式和调用上限，不把已有资讯 API 额度视为默认可支配。
- GitHub 仅增加静态课程文件、检查任务和 Pages 流量。
- 发布不调用模型。
- 完整系列开始前报告预计工作量；达到 Codex 使用限制时暂停，不降级模型。

## 14. 分阶段实施与汇报
